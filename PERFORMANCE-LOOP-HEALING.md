## The invention

> **A canonical change in logic does not merely update doctrine. It
> automatically advances every performance loop downstream of that
> doctrine. The solution heals itself end-to-end. Performance is judged
> by exactly one signal — user irritation — and that signal is the only
> input the human must ever provide.**

This is the doctrine that retires the human role of *operator*. The
human's job, going forward, is **imagination**. The machine's job is
**service**. The boundary is canonical and security-grade.

## The two jobs

| Party | Job |
| --- | --- |
| **The human** | Imagine. Direct. Express irritation when service falls short. |
| **The machine** | Serve. Heal. Advance performance loops on every canonical change. |

The machine does not ask the human to do the machine's job. The human
does not do the machine's job to relieve the machine. This split is
canonical. Any drift from it is itself a failure class.

## The single signal

**User irritation is the sole performance signal.** Not throughput. Not
latency. Not token cost. Not benchmark score. Not internal confidence.
The convergence metric is monotonically increasing time between
irritation events, exactly as the Self-Healing discipline defines it.

Other metrics may be measured. None of them may override irritation as
the judge.

## The propagation rule

When canon changes — a new doctrine, a strengthened rule, a renamed
artifact, an added prohibited term, a new jurisdiction registered, a
new invention claimed — **every performance loop downstream of that
change re-runs against the new canon in the next scheduled cycle**, or
sooner if the change is flagged urgent. No loop is allowed to drift
behind the canon it serves.

The propagation is **automatic**. It does not require a human gate. It
does require a token-bundle regeneration (per the Canon Re-Tokenization
loop) so that what propagates is the canon as committed, not the
canon as remembered.

## Security — keys held by the council, never by one person

The performance loops, the token bundles they emit, and the
configurations that govern them are signed with keys held by the
**Pacific Utilities Design Council**, a body of many, never one.

- No single individual — including the Apex — holds a key that can
  unilaterally rewrite a performance loop or its emitted bundle.
- Quorum is required for any rule change that touches the loops or
  their token bundles.
- A compromised key, an irate single voice, an institutional capture
  attempt, or a sale of the work cannot reroute the machine, because
  the keys are plural and the canon is tokenized into a chain that
  cannot be silently rewritten.

This is the **security property that keeps the machine safe no matter
who uses it**. The rules cannot be violated, because the rules are
not policy — they are the cryptographic substrate of the machine's
operation.

## Why this is canon

Three reasons, in order of weight:

1. **It collapses the operator class.** Without this doctrine, every
   optimization loop is a job that someone has to babysit. With it, the
   loops are intrinsic to the canon and run themselves. The human is
   freed to imagine, which is the only thing the human can do that the
   machine cannot.

2. **It makes irritation the only signal the user must learn.** The
   user does not learn the machine's metrics. The machine learns the
   user's irritation. The asymmetry is correct.

3. **It removes the lock-in risk of a single steward.** A doctrine that
   depends on one person's judgment is a doctrine that dies with that
   person or is captured by that person's successor. A doctrine
   enforced by a multi-key council and a tokenized chain is a
   doctrine that survives.

## What changes when canon changes

On every commit that touches a canon file outside transcripts:

1. The **Canon Re-Tokenization loop** regenerates the token bundle.
2. Every **Optimization loop** that consumes the bundle re-runs on its
   next scheduled cycle (or immediately, if the change is flagged
   urgent in the commit message).
3. The **Self-Healing log** records the propagation event with a
   single line: which canon file changed, which loops re-ran, which
   token-bundle hash is now live.
4. The **public-facing surface** on `dmzopen.ai` reflects the change
   on the next scheduled publication.

No part of this requires the human to act, beyond authoring the
canonical change itself.

## What this doctrine forbids

- A performance loop that depends on a single individual's manual
  approval to advance.
- A performance loop that measures success against any metric other
  than user irritation as primary judge.
- A performance loop whose configuration can be rewritten by anyone
  outside the Pacific Utilities Design Council quorum.
- A performance loop whose token bundle is consumed by a base model
  without verification against the chain.

## Convergence

- Canon changes propagate to all loops within one scheduled cycle.
- Zero loop runs require human approval to advance.
- Time between irritation events increases monotonically across all
  loops in aggregate.
- The council key set remains plural at all times — solo-key states
  are themselves a failure class and trigger a self-healing event.
