# 2026-07-03 · Tim Hawkins 404 — "your public source pack"

## Incident
Kansas City handoff (route position #2). Tim Hawkins, on Messenger, reported "Hey I get an error 404 with 'your public source pack'". Frank was in the middle of setting up the handoff for the Austrians to assess platform investment — the Kenworth HoffmanMurphy operators will be renting from Tim going forward, and Tim needs a working link into the canon to route his own systems in.

## Root cause
Referential integrity failure — trigger class 010. The canon had no page or link named "public source pack". The GitHub repository was public, `main.zip` was auto-generated by GitHub, and GitHub Pages was serving the live canon at `eveglyphdesign.github.io/eve-hyperloop`, but none of the three URLs was surfaced on `index.html`. The 404 was not a broken file — it was a missing signpost.

## Repair applied
Executed repair 010:
- Added a "Public source pack" entry to the Related Material section on `index.html` with three explicit hyperlinks (ZIP, repo, live canon).
- Added a compact "Public source pack · repo · ZIP" entry to the footer links-row.
- Extended the I18N dictionary with `relSrcLink` / `relSrc` in Spanish, English, and French.

## Verification
- `curl -sI` on both the ZIP URL and the GitHub Pages root returned working responses before commit.
- Post-deploy check on `eveglyphdesign.github.io/eve-hyperloop/` will confirm the new links render in all three languages.

## Handoff impact
The Kansas City handoff can proceed. Tim now has three redundant entry points. Any Austrian assessor arriving from Tim's route hits the canon without a 404.

## Lessons
Any verbal handoff referencing an artefact ("send them the pack", "here is the download", "grab the ZIP") must be matched by a visible entry point on the canon before the handoff is considered live. Add a pre-handoff canon-audit step to `/handoffs/README.md`.
