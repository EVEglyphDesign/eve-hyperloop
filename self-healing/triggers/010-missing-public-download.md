# Trigger 010 — Missing public download / 404 on referenced source pack

## Signal
A named external contact reports a 404 or dead link for a resource that was verbally described as available — e.g. "your public source pack", "the download", "the ZIP", "your repo bundle" — where no such visible entry point exists in the live canon.

## Class
Referential integrity failure. The canon has the underlying artefact (the GitHub repository is public, `main.zip` is auto-generated by GitHub, the live pages are served by GitHub Pages), but no page on the canon surfaces those URLs where a first-time visitor would look for them. The 404 is not a broken file — it is a missing signpost.

## Detection
- External party reports "404" for a resource named in a verbal or Messenger handoff.
- Root-path check: no `<a>` on `index.html` or the footer links-row points to `github.com/EVEglyphDesign/eve-hyperloop`, `main.zip`, or the Pages URL.

## Why this class matters
The Kansas City handoff (route position #2 — Tim Hawkins) is the assessor route for platform investment. A dead link at the handoff kills momentum and reads as amateur hour to the receiving party. The canon must surface every artefact it depends on. If the mouth says "source pack", the page must ship a "Public source pack" link.
